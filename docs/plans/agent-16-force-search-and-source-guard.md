### Part A — 검색 없이 답하지 않게 한다

**판정 규칙**: "이번 턴" = 상태 메시지 목록에서 **마지막 `HumanMessage` 이후**. 그 구간에 `ToolMessage` 가 하나도 없으면 아직 근거가 없는 상태다.

**2026-09-29 실측으로 G2 방식 확정** (리드 판단 기록 (4) 참조). `tool_choice` 는 `ChatOllama` 가 **조용히 무시**하므로 쓰지 않는다.

- `agent` 가 tool_calls 없이 답하려 하고 이번 턴 `ToolMessage` 가 0건이며 **아직 강제하지 않았으면** → 조건부 엣지로 **`force_search` 노드**로 보낸다.
- `force_search`: `standalone_question`(없으면 마지막 사용자 질문)을 query 로 `search_confluence`·`search_openapi` **둘 다** 직접 호출하고, **합성 `AIMessage(content="", tool_calls=[...])` + 대응 `ToolMessage(tool_call_id=...)` 쌍**을 상태에 넣은 뒤 `agent` 로 되돌린다(표준 쌍 형태를 쓴다 — 실측에서 정상 동작).
- **턴당 1회 제한**: 상태 필드 `forced: bool` 로 판정한다. **`rewrite` 노드가 매 턴 `forced=False` 로 초기화**한다(rewrite 는 모든 턴의 첫 노드이므로 리셋 지점으로 적합하다). `recursion_limit` 에 의존하지 않는다.
- **UI 표시 일관성**: `stream_events` 는 현재 `updates` 페이로드의 **`agent` 키만** 보고 `search` 이벤트를 만든다. 합성 tool_calls 는 `force_search` 노드에서 나오므로 그대로 두면 **검색이 실제로 일어났는데 화면에 `[검색]` 줄이 안 뜬다.** `updates` 의 **모든 노드 키**를 훑어 tool_calls 를 찾도록 바꾼다(tools 노드 갱신에는 tool_calls 가 없어 부작용 없음).
- **무한 루프 방지**: 강제는 **턴당 1회만**. 강제 후에도 도구 결과가 없으면 그대로 답하게 둔다(`recursion_limit` 에 의존하지 않는다).
- 부작용 수용: "안녕" 같은 인사에도 검색이 1회 돈다. 검색 결과가 비면 모델이 인사로 답하면 된다. 이 동작을 게이트 A4 로 확인만 하고 허용한다.

### Part B — 출처 위조 차단 (안전망)

Part A 가 동작해도 모델이 URL 을 잘못 적을 수 있으므로 별도로 막는다.

- `src/web/app.py` `stream_events` 가 이번 턴의 `ToolMessage` 본문에서 **URL 집합**을 모은다(`https?://\S+`).
- 스트림이 끝날 때, 누적된 답변 텍스트의 URL 중 그 집합에 **없는 것**이 있으면 `done` 직전에 새 SSE 이벤트를 보낸다:
  - `event: warning`, `data: {"kind": "unverified_source", "urls": [...]}`
- UI 는 답변 하단에 눈에 띄는 경고 줄을 붙인다: `⚠ 검색 결과에 없는 링크가 포함돼 있습니다: …`
- **답변 본문을 서버가 고치지 않는다**(모델 출력을 조작하지 않고 표시만 한다). 체크포인터 저장 내용도 불변.
- `[검증]` 기존 UI 테스트 `test_sse_event_names_match_server_contract` 가 처리 이벤트를 `{search, token, done, error}` 부분집합으로 고정하고 있다 → **허용 수정 대상**(집합에 `warning` 추가).

### 변경하지 않는 것

`SYSTEM_PROMPT`·`REWRITE_PROMPT` **문구**(위 제약 때문에 절대 손대지 않는다), `build_graph` 시그니처, 도구 이름·인자·docstring, `/check`·`/v1/chat/stream`·`/v1/threads/...` 경로와 요청 스키마, 설정 스키마, 의존성.
