## 원인 1 — RAG: 근거가 구조적으로 부족하다 `[검증]`

### 전달 상한이 정답보다 작다

- 청크 1개 = 오퍼레이션 1개 단위(`chunk_id` = `general-chatbot-api:POST:/v3/init/...#0`).
- `[rag] top-k=6` (`resources/config_local.ini:5` → `src/tools.py:28,33`).
- **6 < 9.** 한 번의 검색으로는 원리적으로 9를 셀 수 없다.

### 실제 질문에서는 더 나쁘다

`POST /v1/search`, `source=openapi`, `top_k=6` 직접 실측:

| 질의 | 정답 9개 중 포함 | 타 서비스 혼입 |
|---|---|---|
| "general chatbot api 전체 목록" | 6/9 | 없음 |
| "general chatbot api API 개수" | 5/9 | message-api 1 |
| **"general chatbot api의 총 api 개수가 몇 개야?"** (실제 질문) | **2/9** | **message-api 4** |

`source=confluence` 는 3개 질의 모두 0/9. 세어도 **오염된 것을 센다.**

### 설정을 올려도 해결되지 않는다

- RAG 서버가 `top_k` 를 **20으로 하드 캡**한다(`RAG/src/dto/ask_dto.py:40`). 25/30/40/50 모두 `422 less_than_equal le:20`.
- `top_k=20` 으로 올려도 한 질의에서 general-chatbot-api 오퍼레이션은 **7/9** 에 그쳤다.
- 인덱스에 이 서비스 청크가 오퍼레이션 9 + 스키마 7 = 16개라, k 를 키우면 **스키마 청크가 슬롯을 잠식**한다.
- 검색은 BM25 0.4 + 벡터(bge-m3) 0.6 앙상블의 **유사도 상위 k개**다(`RAG/src/service/retriever_service.py:62-77`). "관련 있는 것 몇 개" 를 위한 구조이지 **"조건에 맞는 전부" 를 위한 구조가 아니다.** 메타데이터 필터로 전량 열거하는 경로가 없다.

### 우회로도 막혀 있다

`call_api(service="general-chatbot-api", path="/openapi.json")` 실측 → 반환 2,090자, 끝에 `…(본문이 잘렸습니다. 전체 19390자)`.
`[api] max-response-chars=2000` 이 **89.69% 를 잘라** 9개 중 **2개만** 남는다(`src/api_tool.py:32-36`).
게다가 페이징·오프셋 인자가 없어 잘린 뒷부분을 이어받을 방법이 없다.

### 집계 전용 경로 자체가 없다

`route_after_agent`(`src/agent.py:177-184`)의 분기는 `tools / force_search / END` 뿐이고 질문 유형 분류가 없다.
`src/` 전체에 집계/카운트 노드·도구가 존재하지 않는다.
시스템 프롬프트에도 **"검색 결과는 상위 N건일 뿐이니 총 개수를 단정하지 말라" 는 지침이 없다.**
규칙 5("추측하지 않는다")는 *없는 내용*은 막지만 ***불완전한 근거***는 막지 못한다 — 이번 실패가 정확히 그 틈이다.

## 원인 2 — LLM: 근거를 다 줘도 합계를 틀린다 `[검증]`

원인 분리를 위해 **근거를 100% 완전히 준 상태**에서 동일 모델(qwen3:14b, temperature=0, num_ctx=16384)에 직접 질의. 각 3회.

| 케이스 | 컨텍스트 | 답 | 정답 9 | 일관성 |
|---|---|---|---|---|
| **A** 짧고 정규화된 9줄 경로 목록 | 541자 | **9** | ✅ | 3/3 |
| **B** openapi.json **전문**(절단 없음) | 19,444자 | **8** | ❌ | 3/3 |
| **C** 운영과 동일한 `format_chunks` 포맷, 9개 오퍼레이션 **전부** | 8,803자 | **10** | ❌ | 3/3 |

**B·C 모두 9개를 하나도 빠짐없이 정확히 열거해놓고 합계만 틀렸다.**

- B: 1~9번을 올바르게 나열하고 머리글에 `8`, 그리고 스스로 모순된 사족 —
  `"(총 9개의 API 경로가 존재하지만, 중복된 기능을 가진 경로는 제외하고 고유한 기능을 가진 API는 8개입니다.)"`
- C: 1~9번을 정확히 나열한 뒤 **존재하지 않는 10번째를 지어냈다** —
  `"10. GET /v2/dialogs/... (이미 3번으로 중복, 하지만 URL 구조가 다르므로 별도로 계산)"`

→ **RAG 를 고쳐 9개를 전부 전달해도 그것만으로는 정답이 나오지 않는다(C 가 그 반례다).**
→ 다만 **A 가 3/3 정답인 것이 탈출구다.** 실패 조건은 "세는 능력 부재" 가 아니라 **"장황한 스펙 텍스트에서 집계할 때 무너짐"** 이다.

### 이 진단에서 끌어낸 원칙

> **숫자는 LLM 에게 세게 하지 않는다. 코드가 세고, LLM 은 전달만 한다.**

## 함께 발견한 별개 결함 2건 (이번 오답과 원인이 다름)

### D2. 출처 오귀속이 경고를 통과한다 `[검증]`
