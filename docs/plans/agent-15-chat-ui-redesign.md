### 구현 지침 (충돌 예방 — 중요)

1. **D5·D6 은 `renderMarkdown` 을 고치지 말고 후처리로 한다.** 렌더 결과를 받은 뒤 별도 함수(`decorateCodeBlocks(container)`)가 `<pre>` 를 감싸 상단 바를 붙인다. 이유: agent-03 의 렌더러 테스트가 `renderMarkdown` 의 출력 DOM을 19케이스로 비교하고 있어, 렌더러를 고치면 그 테스트들이 줄줄이 깨진다. **후처리 방식이면 렌더러 테스트는 그대로 green.**
2. **복사 버튼은 `navigator.clipboard.writeText` 를 쓰되, 없으면 조용히 버튼을 만들지 않는다**(테스트용 DOM 셰임·비보안 컨텍스트 대응).
3. `textarea` 로 바꿔도 **`id="question"`·`id="send"`·`id="reset"`·`id="log"`·`id="form"` 은 유지**한다(기존 테스트·스크립트 참조).
4. D9 의 "하단 고정"은 기존 `scrollIntoView` 호출을 대체하되, 사용자가 위로 올린 상태를 `scrollTop`/`scrollHeight` 로 판별한다.

### D13 (2026-09-29 사용자 피드백 "텍스트가 조금 더 커도 될 것 같다, 잘 안 보인다")

글자 크기를 전반적으로 키우고, **이후 재조정이 한 곳에서 되도록 기준 변수를 도입**한다.

```css
:root { --fs: 17px; }        /* 본문 기준. 이 값만 바꾸면 전체가 따라 움직인다 */
```

| 대상 | 목표 | 비고 |
|---|---|---|
| 본문(답변·질문) | **17px**, `line-height: 1.7` | 기존보다 크고 줄 간격도 넓힘 |
| 마크다운 제목 | h1 **22** / h2 **19** / h3 **17.5** / h4 **16** | 기존(18/16/15/14)은 본문과 차이가 거의 없어 위계가 안 보였다 |
| 코드 블록·인라인 코드 | **14px** | 기존 12px 은 특히 읽기 어렵다 |
| 도구 호출 pill(`[검색]`/`[호출]`) | **13px** | |
| 헤더 제목 | **17px** | |
| 예시 카드 | 질문 문구 **15~16px**, 카테고리 라벨 12~13px | |
| 입력창(`textarea`) | 본문과 같은 **17px** | 입력·출력 크기가 다르면 어색하다 |

- 가능한 곳은 `--fs` 기준 상대값(`calc()`·`em`)으로 쓰고, 고정이 나은 곳(라벨·pill)만 px 로 둔다.
- 라이트/다크 모두 동일하게 적용한다(색 변수만 분리, 크기는 공유).
- **더 키우거나 줄이는 후속 요청은 `--fs` 한 줄 수정으로 처리한다**(사용자가 직접 고칠 수 있게 주석을 단다).
